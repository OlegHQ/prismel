# PXUI, shell, graph, and viewport architecture

## Does the current UI/editor architecture enforce ownership and presentation boundaries?

### Takeaway
The existing library boundaries are sensible; another UI engine or a broad library split would add maintenance work without solving the observed defects. The priority is enforcing input ownership at the viewport boundary and applying pane intents after UI construction.

### Cited Findings
- `pxui_shell` depends only on `prismel`, `editor_core`, and `pxui`; `pxui_graph` depends on those plus `procedural`. This matches the documented separation of generic chrome and SOP presentation. [Shell dependencies](/Users/snowbear/WORK/GIT/prismel/lib/pxui_shell/dune:1), [Graph dependencies](/Users/snowbear/WORK/GIT/prismel/lib/pxui_graph/dune:1).
- PXUI has one event router, hit list, active pointer owner, and focus owner. Its ordered event fold cancels capture/focus/composition on `WindowFocusLost` and routes wheel against scroll/blocking flags. Viewport handles and graph tiles build `Ui.box` and consume `Ui.signal`, so these do not constitute additional widget hit-test engines. [Router](/Users/snowbear/WORK/GIT/prismel/lib/pxui/ui.ml:607), [Viewport handles](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/viewport3.ml:372), [Graph canvas](/Users/snowbear/WORK/GIT/prismel/lib/pxui_graph/pxui_graph.ml:1499).
- The editor's documented invariant says panes return intents and `Core.update` dispatches them; code in `Ui.frame` must not mutate the model or refs. Actual `build` applies graph intents through `Doc.apply`, tree intents through `apply_tree`, inspector edits through `Edit_graph.replace_node`, and handle edits through `Edit_graph.apply_parameters`, and mutates a local `live` ref. The document operations are immutable, so this is a phase-boundary violation rather than proof of mutable document corruption. [Rule](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/AGENTS.md:14), [Graph/tree edits in build](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:799), [Local ref mutation](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:829), [Inspector edits](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:865), [Handle edits](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:886), [Builder runs within frame](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:977).
- **P1, reproduced: command-palette wheel input changes the camera behind it in both dimensions.** `Core.input` masks pointer events only when `result.grab` is true; that flag originates from viewport handles, not general PXUI/modal ownership. `Environment.update_with` sends this input to `V.navigate`; both camera adapters rely on control-area geometry. Popup blocking suppresses other PXUI scroll targets but does not suppress the camera's independent event fold. [Core output](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:1178), [Handle-only grab](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:876), [Navigation](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/environment.ml:423), [Camera adapters](/Users/snowbear/WORK/GIT/prismel/lib/pxui/camera_controls.ml:70), [Camera wheel](/Users/snowbear/WORK/GIT/prismel/lib/prismel/easy_camera2.ml:238), [Popup root](/Users/snowbear/WORK/GIT/prismel/lib/pxui/ui.ml:1452).
- The preserved reproduction opens `Space /`, allows one layout frame, and sends a wheel at `(330,300)` in a 900×640 editor. Output on this checkout: `3D palette wheel: distance 7 -> 6.20844306`, `2D palette wheel: zoom 1 -> 1.12749685`. [Reproduction source](/Users/snowbear/WORK/GIT/prismel/research_notes/Editor%20architecture%20and%20maintenance/ui-repro.ml:1).
- **P2, reproduced: a hidden shell skips cancellation.** `Shell.frame ~visible:false ~overlay:None` never calls `Ui.frame`, so a focused text widget stays focused after an input frame containing `WindowFocusLost`; no pruning or capture cancellation runs. The same reproduction prints `shell focused before hide: true` and `hidden shell focus after WindowFocusLost: true`. [Hidden branch](/Users/snowbear/WORK/GIT/prismel/lib/pxui_shell/pxui_shell.ml:797), [Actual cancellation](/Users/snowbear/WORK/GIT/prismel/lib/pxui/ui.ml:686), [Existing hidden-shell test misses this case](/Users/snowbear/WORK/GIT/prismel/lib/pxui_shell/test_shell.ml:89), [Reproduction source](/Users/snowbear/WORK/GIT/prismel/research_notes/Editor%20architecture%20and%20maintenance/ui-repro.ml:33).
- **P2, keyboard-accessibility gap:** button/toggle rows have clickable/blocking flags and return pointer `clicked`; focus is assigned only on left pointer press, and nontext controls have no keyboard activation path. Text focus is implemented, but Tab traversal across inspector controls is not. This limits keyboard-only editing; it is not proof about the complete native accessibility tree. [Kit flags](/Users/snowbear/WORK/GIT/prismel/lib/pxui/ui.ml:1367), [Button/toggle activation](/Users/snowbear/WORK/GIT/prismel/lib/pxui/ui.ml:1494), [Focus assignment](/Users/snowbear/WORK/GIT/prismel/lib/pxui/ui.ml:634).
- **P3, bounded-cache contract gap:** `modal_heights` is a persistent hash table keyed by modal identity; every encountered modal key is retained with no removal/capacity. The editor currently uses a small fixed set of keys, so observed editor impact is low, while the public generic API permits dynamic keys. [Table creation](/Users/snowbear/WORK/GIT/prismel/lib/pxui/ui.ml:464), [Only update/read](/Users/snowbear/WORK/GIT/prismel/lib/pxui/ui.ml:1476).
- Lifecycle ownership is otherwise explicit: the editor closes the UI; `Ui.destroy` destroys its atlas and internally owned fonts while borrowing a supplied font. No duplicate lifecycle path was found in this scope. [Editor close](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:1207), [UI destroy](/Users/snowbear/WORK/GIT/prismel/lib/pxui/ui.ml:471), [Public borrowed-font contract](/Users/snowbear/WORK/GIT/prismel/lib/pxui/ui.mli:40).

### Inferences
- Smallest routing fix: expose/use PXUI's ownership for the view pane's unconsumed ordered events, with the view root as a permitted owner, and preserve gesture ownership through release/cancellation. A plain `wants_pointer` boolean would suppress the viewport itself because its pane root is clickable. Do not add another hit test or filter by current mouse position; drag ownership survives leaving the original rectangle.
- Smallest hidden-shell fix: always advance the single `Ui.frame`; when hidden, build only any overlay, otherwise no boxes. This routes cancellation, prunes vanished controls, and clears stale scene/text regions with one shared path.
- Remove the local `live` ref immediately by returning its value with the panel result. Then move document application after `Shell.frame` using the existing typed graph/tree/parameter intents; preserve an explicit ordered semantic rule for a graph selection and inspector edit in the same frame. Do not build a new generic message bus.
- Keep current public libraries. Internally splitting `pxui_shell.ml` into Layout/Tree/Prompt/Inspector files is a navigation improvement only, not an architectural repair. A separate library is justified only if a second real host requires a smaller dependency set or an independently enforceable pure boundary.

### Gaps
- The modal wheel defect is directly reproduced; right/middle drag leakage and World layer edits behind popups follow the same unfiltered path but were not separately exercised.
- The hidden-shell defect is directly reproduced via its public API. The normal editor's leader workflow ordinarily cannot hide UI while text focus owns keys; this does not eliminate the shell cancellation bug, but limits claims about ordinary editor triggers.
- No native Accessibility Inspector/VoiceOver session was run, and no claim that the native window exposes zero accessibility is made. The toolkit does not expose widget role/value/action metadata in its current public interface.

## Which external design patterns fit this editor without overbuilding it?

### Takeaway
Immediate-mode UI is compatible with one application-owned immutable document and retained interaction state. Input ownership must be an explicit output of the UI system, and domain state must remain independent of presentation.

### Cited Findings
- Dear ImGui defines the immediate-mode paradigm at the API boundary, favoring application data ownership and avoiding duplicate data synchronization; it does not forbid internal retained state. This supports keeping PXUI's retained boxes/focus while the editor owns its document. [Dear ImGui paradigm](https://github.com/ocornut/imgui/wiki/About-the-IMGUI-paradigm).
- Dear ImGui directs hosts to always submit input to the UI and use its capture flags to decide whether underlying application logic receives input; checking whether the mouse merely hovers a window fails for dragging/popups. It also calls out matching key-up filtering to the earlier key-down owner. [Dear ImGui integration FAQ](https://github.com/ocornut/imgui/blob/master/docs/FAQ.md#q-how-can-i-tell-whether-to-dispatch-mousekeyboard-to-dear-imgui-or-my-application).
- Qt Graphics View separates the scene from its views and centralizes focus/event propagation. The item accepting a press becomes mouse grabber and remains so until the release completes. This is a transferable ownership rule, not a recommendation to adopt Qt or retained widgets. [Qt Graphics View](https://doc.qt.io/qt-6/graphicsview.html), [QGraphicsScene events](https://doc.qt.io/qt-6/qgraphicsscene.html).
- Apple's custom-control guidance requires exposing appropriate roles, information/actions, and notifications; drawn controls without separate views can be represented by accessibility elements. This supports deriving accessibility metadata from PXUI's existing boxes and routing actions through existing intents rather than constructing another UI model. The linked guide is archived, so current platform API details should be checked during implementation. [Apple custom controls](https://developer.apple.com/library/archive/documentation/Accessibility/Conceptual/AccessibilityMacOSX/ImplementingAccessibilityforCustomControls.html).

### Inferences
- Apply these patterns as invariants: a pointer gesture has one owner until terminal events; a focused control receives text and keyboard input; a dismissed/hidden control relinquishes ownership; UI construction produces intents and rendering; one document reducer validates/applies the intents and records history.
- Prefer one small ownership/consumption API on `Ui` or `Shell` over per-pane booleans. Panes should be able to supply keys/ownership categories without knowing renderer/backend details.
- For accessibility, add keyboard focus traversal/activation using the same boxes and typed intents first, then native semantic elements. Retain the kit's geometry and paint output.

### Gaps
- The sources establish ownership and separation patterns, not a performance claim about Prismel. Do not cite them as evidence for a particular library split, a generic ECS, a plugin system, or a reactive framework.

## What checks make the plan reviewable, and what did validation actually show?

### Takeaway
The logic/dependency baseline passes, but targeted regression checks are missing for UI-to-viewport ownership and hidden-shell cancellation. Native render validation includes one reproducible mismatch whose root cause is unresolved; PXUI golden parity passes when isolated.

### Cited Findings
- Root reported focused logic tests, `@check`, and dependency gate passing: 44 libraries, 41 rules, zero listed exceptions. This supports dependency structure, not interaction completeness. [Dependency gate implementation](/Users/snowbear/WORK/GIT/prismel/test/dependency_gate.ml:1).
- Serial `dune build @lib/pxui/test_ui_parity` passed: `PXUI overlay parity: exact`; `PXUI Ui parity: 640x600 at 2x, 272 permitted pixel changes`. The earlier simultaneous native run failed overlay parity, which was not reproduced serially. [Golden comparator](/Users/snowbear/WORK/GIT/prismel/lib/pxui/test_ui_parity.ml:88).
- Serial `dune build @test/test_prismel_editor` failed at `test/test_prismel_editor.ml:883`; invoking `_build/default/test/test_main.exe test_prismel_editor` independently reproduced it. The assertion compares editor composition with a directly drawn prepared mesh from the render camera. Saved images visually differ, so this is not merely different PNG metadata. [Comparator](/Users/snowbear/WORK/GIT/prismel/test/test_prismel_editor.ml:866).
- Unsandboxed failure artifacts: `/private/var/folders/lk/l8ypry253l3g36ty86b1y75c0000gn/T/sketch-ui-look2737fc/look-000000.png`, `look-000001.png`, `look-000002.png`; each is 400×300. The composed cube is positioned differently from the directly drawn render-camera cube. The editor additionally composes object transforms/scene lights, so mismatched test composition is a plausible cause requiring investigation. [Editor composition](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/environment.ml:315), [Placed nodes/lights](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/viewport3.ml:241).

To rerun without changing library code, copy it into a temporary in-repo Dune executable with `(libraries prismel_editor procedural pxui pxui_shell)` and run `dune exec <temporary-dir>/ui_repro.exe`; remove the temporary source/stanza afterward.

### Inferences
- P1 acceptance: parameterize Editor2/Editor3; show a modal or graph menu over the viewport; wheel/right/middle/left gestures must leave camera/document unchanged while the popup receives them. A viewport-owned drag must continue across another pane and terminate on release/focus loss. A graph-owned drag must never start viewport navigation. Include same-frame popup opening/closing and press/release sequences.
- P2 acceptance: focus text/IME or capture a slider, then hide/collapse the owning pane; send `WindowFocusLost` and pointer cancellation; ownership must clear, scene must lose vanished text regions, reopening must not commit a stale gesture or consume shortcuts.
- Reducer acceptance: one frame containing selection plus a parameter edit applies to the intended stable node ID; cancel/failed parameter validation leaves the document/history unchanged; widget construction itself cannot save files or record history.
- Native validation must run finite windowed examples sequentially. Resolve the current editor framebuffer assertion before calling the editor solid; compare equivalent world placement/lights/viewport/lens, then pixels. Do not refresh the golden or weaken the comparison without proving intended behavior.
- Keyboard/accessibility acceptance: keyboard traverse inspector widgets, activate toggles/buttons, change numeric/choice values, dismiss modal, and return focus to the previous owner; native accessibility clients see role/label/value and route activation through the same command path.

### Gaps
- Renderer mismatch root cause is unproven; report a failing native assertion rather than declaring a camera bug. The original parallel PXUI mismatch may reflect native resource/process contention, but causality was not measured.
- No additional performance benchmark was run. Source size and internal mutable presentation caches alone are not correctness violations.
