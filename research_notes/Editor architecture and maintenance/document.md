# Editor document, history, persistence, and cooking

## Is the document architecture sound, and where does it violate its own rules?

### Takeaway
The immutable document, bounded snapshot history, typed graph edits, and latest-request worker are useful foundations. The main problem is that document validity and transaction semantics are distributed across presentation code, loader code, and environment callbacks; adding libraries alone would preserve this problem.

### Cited Findings
- One `Document.t` owns scene graph, per-object networks, active camera, and sketch settings; selection and open level stay outside history. Layout uses an integer map and updates changed tile IDs. Preserve these choices. — [document.ml](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/document.ml:14), [incremental edit](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/document.ml:52)
- History is small and bounded, with explicit Step/Gesture/Burst/Repair policies and labelled entries; focused tests cover capacity, grouping, seal, undo/redo and labels. There is no evidence that replacing snapshots with command objects is warranted. — [History](/Users/snowbear/WORK/GIT/prismel/lib/editor_core/editor_core.ml:4), [tests](/Users/snowbear/WORK/GIT/prismel/lib/editor_core/test_history.ml:1)
- The shipped rule says panes return intents and `Core.update` is the one dispatcher, with no model/ref mutation inside `Ui.frame`. The actual UI builder applies `Doc.apply`, tree edits, node parameter replacement, settings edits, and handle edits before returning the frame result. It also mutates a local `live` ref. These edits construct immutable values rather than corrupting the input model, but the stated phase boundary is not enforced. — [rules](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/AGENTS.md:12), [builder edits](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:799), [local ref](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:829), [parameters](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:865), [handles](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:884)
- History/document synchronization has several writers: normal frame commit, `scene_edit`, `set_settings`, and `edit_node`; scene edit repair deliberately amends the present. View gestures run after `Core.update`. This makes the meaning of one user transaction dependent on frame order and whether it originated in UI or the environment. — [frame commit](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:1055), [scene_edit](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:1189), [settings](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:1213), [view edits](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:1240), [environment](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/environment.ml:370)
- All document changes while the left button is held share `Gesture 0`; map/sun/world edits use `Gesture 1`; release or focus loss seals the history. A gesture ID describes a path, not the control, node, or operation. Mixed commands during a drag can coalesce unrelated changes. This is a source-level risk rather than a reproduced native failure. — [merge choice](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:1062), [seal](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:1063), [view gesture](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:1249)
- ProseMirror's official guide specifies one controlled update point and transactions that compute a new immutable editor state in one shot. Qt distinguishes command compression from explicitly grouped macros. The applicable idea is an explicit edit boundary/grouping policy, not adopting those frameworks or their object hierarchy. — [ProseMirror introduction](https://raw.githubusercontent.com/ProseMirror/website/master/markdown/guide/intro.md), [ProseMirror state](https://raw.githubusercontent.com/ProseMirror/website/master/markdown/guide/state.md), [Qt undo stack](https://doc.qt.io/qt-6/qundostack.html)

### Inferences
- Smallest maintainable change: keep existing libraries, move pure document application and history commit into one internal reducer with a small concrete edit payload carrying label, effects, and merge policy. UI returns intent values; environment camera/world edits use the same commit helper. Do not build a generic transaction/plugin framework.
- Separate `Document` from `Pxui_graph` conversion helpers first at module level: the record and validity checks need only procedural graph/settings types; `of_view`, `edit`, `to_view` are presentation adapters. Promote a library only if a second actual consumer or an enforceable dependency gate needs it.
- One check must assert `Core.doc == History.present core.history` after all public edit paths, undo/redo, loading, camera following, settings changes, and pointer gestures. Another should prove different commands cannot merge merely because the mouse is held.

### Gaps
- No native mixed-command-during-drag failure was reproduced in this subtask; do not label this as proven data corruption.
- Snapshot count is bounded, but retained memory depends on custom nodes and structural sharing. No heap benchmark was run; do not claim history memory is practically bounded in bytes or that a new history representation is needed.

## What are the major persistence and document-validity risks?

### Takeaway
The serializer preserves existing files with temporary-file rename, but the loader does not validate the full document invariant. Empty editable networks cannot round-trip, and accepted geometry objects without networks can lead the 2D editor into an invalid level.

### Cited Findings
- **P1, self-generated save cannot reload an empty network.** Delete every SOP tile: `Doc.apply` allows the network to become empty, `Document.displayed_of` retains an integer display ID, serialization writes `nodes=[]` and that display integer, then `rebuild` resolves the display against an empty mapping and rejects it as a missing node. The same applies to an empty scene. The file exists and is not torn; the user-visible fault is rejection of a legitimate saved state, not proven overwriting/loss of an older file. Crash-dump presets use the same serializer. — [delete](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/doc.ml:50), [empty display](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/document.ml:34), [serialize](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/preset.ml:53), [missing-node check](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/preset.ml:234), [display rebuild](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/preset.ml:257), [crash save](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/environment.ml:480)
- **P1, accepted presets can violate host assumptions.** v2 `networks` may be absent (decoded as `[]`), network entries whose object is missing are silently skipped, and no check requires every geometry/world to own a network or every network to have the right owner kind. `Core.network` and `view_of` use `Option.get`. For Editor2 (scene_level=false), load chooses the first geometry without checking its network; a no-geometry preset retains the old Inside ID. Both paths can fail during `view_of`/`Document.to_view`. — [optional networks](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/preset.ml:177), [skip missing owners](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/preset.ml:303), [unchecked lookup](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:122), [view lookup](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:141), [post-load level](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:1080), [2D host](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/viewport2.ml:13)
- Saved-node IDs are not checked for duplicates before old-to-new mapping. Network ownership duplicates overwrite map entries. Numeric layout parsing accepts nonfinite floats; parameter value parsing does too, although Param may reject some values downstream. This is incomplete validation at the file boundary; exact downstream failures were not reproduced. — [node decoding](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/preset.ml:113), [mapping](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/preset.ml:213), [network overwrite](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/preset.ml:313)
- Code-defined nodes intentionally rebind by runtime integer ID. A recreated graph with different IDs is rejected, and the existing test explicitly expects rejection. This is a known persistence compatibility cliff after code graph changes, not an untested claim of ID corruption. Stable explicit code-node identifiers are needed only if cross-version sketch presets are a requirement. — [rebind](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/preset.ml:225), [compatibility test](/Users/snowbear/WORK/GIT/prismel/test/test_prismel_editor.ml:764)
- The shared store creates a temp file in the destination directory, closes it and renames it, with cleanup on errors. Retain this; Qt's official document-save interface uses the same broad pattern. This proves avoidance of partial destination files on ordinary write failure, not power-loss durability (no fsync). — [Store.save](/Users/snowbear/WORK/GIT/prismel/lib/editor_core/store.ml:11), [store failure test](/Users/snowbear/WORK/GIT/prismel/lib/editor_core/test_store.ml:27), [Qt safe save](https://doc.qt.io/qt-6/qsavefile.html)
- Existing preset tests cover v1 migration, v2 round trip, unknown code node, corrupt JSON, sanitization, deletion, and workspace load/undo. They do not cover empty networks, missing/wrong network owners, duplicate IDs, host-incompatible scene documents, or nonfinite layout coordinates. — [preset tests](/Users/snowbear/WORK/GIT/prismel/test/test_prismel_editor.ml:703)

### Inferences
- Ordered fix 1: make empty networks representable consistently (an optional displayed node, or another explicit empty-network representation); saving and loading must accept every state the editor itself can produce. Acceptance: delete all nodes, save, reload, undo/redo load, and crash-dump reload preserve the empty state in both Editor2 and Editor3. Decide whether an empty SOP clears the preview; currently compile failure retains the previous graph/output ([Cook fallback](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/cook.ml:124)).
- Ordered fix 2: add one pure `Document.validate`/normalization boundary used before installing loaded state. Reject duplicate IDs, unknown owners, kind mismatches, invalid display and active-camera references, missing required networks, nonfinite coordinates, and host-incompatible documents. Acceptance: every rejected load returns a useful Error and leaves document, history, viewport, and last good preview unchanged. Prefer rejecting ambiguous/malformed content to silently inventing geometry.
- Ordered fix 3: use one validated level resolver after load/undo/remove. Editor2 must either explicitly reject a scene with no valid geometry network or support an intentional empty state; never retain a dangling Inside ID.
- Do not add autosave, new migration frameworks, content-addressed storage, or a persistence library split until their requirements are concrete. Keep envelope parsing and primitive values reusable; graph reconstruction remains procedural/editor-specific.

### Gaps
- Full delete/save/reload UI gesture repro has not been run here; the actual serializer/loader empty-scene roundtrip and public Editor2 browser load were reproduced below.
- Existing store tests do not simulate disk full, rename failure, cleanup failure, or abrupt process termination. Add one focused failed-write check if modifying the writer; do not claim full durability from rename alone.

## Does cooking preserve freshness, reuse, and maintainable concurrency?

### Takeaway
The worker's bounded latest-request behavior is sound and already tested. The host's prepared-value reuse has a proven physical-equality error plus missing settings/context provenance; fixing only the equality expression would introduce an animation bug.

### Cited Findings
- **P1 performance contract failure, proven:** `previous_settings != Some settings` constructs a new option wrapper and compares wrapper identity. It is true even when the Settings payload is identical, so the unchanged-piece reuse branch never runs. Every submitted multi-object cook therefore re-prepares all objects rather than retaining unchanged prepared values as its comment promises. This is a proven branch defect, not a measured latency/allocation claim. — [reuse code and intent](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/cook.ml:159)
- On poll, a completed Displayed value is labelled `Some settings` from the current update, although `prepare` captured the settings at submission. If settings changed before this poll (e.g. `set_settings` immediately before update), a completion prepared under A is briefly stamped B before the B job submits. Worker request freshness alone does not establish the host's metadata provenance. — [poll stamp](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/cook.ml:140), [captured settings](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/cook.ml:162), [poll precedes new submit](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/cook.ml:178), [settings setter](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:1213)
- **Do not patch equality in isolation.** The reuse predicate only checks object ID and physical Graph identity. Schedule recooks Time/Frame-dependent graphs when timeline context changes while preserving the same Graph value. If the currently dead reuse branch is enabled without an output/context key, it will retain old prepared geometry on dynamic cooks. This is a source-proven consequence of the proposed one-line correction, not a current observed freeze. — [reuse predicate](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/cook.ml:167), [dynamic schedule](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/schedule.ml:25)
- Async_cook keeps one active and one pending request, cancels superseded contexts, drops completions unless request.id equals latest_id, catches exceptions, and joins the worker on close. Existing latest-request test submits a slow request then a faster replacement and asserts only the replacement publishes; it also checks idempotent close. Preserve this worker instead of introducing a task/job abstraction. — [worker publication](/Users/snowbear/WORK/GIT/prismel/lib/procedural/async_cook.ml:94), [submit bound](/Users/snowbear/WORK/GIT/prismel/lib/procedural/async_cook.ml:126), [close](/Users/snowbear/WORK/GIT/prismel/lib/procedural/async_cook.ml:165), [regression](/Users/snowbear/WORK/GIT/prismel/lib/procedural/test_procedural.ml:185)
- React's official example explicitly ignores obsolete asynchronous responses. Prismel already does this at worker request level; the useful additional principle is to carry and compare the snapshot that produced a result, including settings and output/context identity. This is an analogy, not a recommendation to use React. — [React stale result handling](https://react.dev/reference/react/useEffect)
- `Async_cook` documents that prepared values must be target-neutral and SDL/GPU work stays on the initial domain. Editor2/3 expose the prepare callback without repeating that requirement near create/run. Copy the restriction into the high-level API where users supply callbacks. — [worker contract](/Users/snowbear/WORK/GIT/prismel/lib/procedural/async_cook.mli:1), [Editor3 callback](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/prismel_editor.mli:192), [Editor2 callback](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/prismel_editor.mli:387)
- Tests cover initial asynchronous cook, display switching, framing while busy, settings recook and undo, scene/transform edits not recooking SOPs, and exact one-vs-four-domain geometry. They do not count prepares for unchanged objects in a multi-object cook or test timeline/context freshness of prepared reuse. — [editor tests](/Users/snowbear/WORK/GIT/prismel/test/test_prismel_editor.ml:111), [settings](/Users/snowbear/WORK/GIT/prismel/test/test_prismel_editor.ml:579), [scene edits](/Users/snowbear/WORK/GIT/prismel/test/test_scene_tree.ml:94), [domain equality](/Users/snowbear/WORK/GIT/prismel/test/test_scene_tree.ml:222)

### Inferences
- Ordered fix 4: carry the submission settings in `Displayed` (or an explicit concrete result record), and key reuse by settings payload plus output identity/context dependencies. An output record/geometry identity can work only if `Session.output` sharing is understood and includes instances; a graph pointer by itself cannot. Keep this internal to Cook.
- Acceptance: two static objects, edit only one -> unchanged object's prepare counter remains unchanged; changing settings -> both prepare; same graph with Time/Frame-dependent output -> successive prepared results differ; delayed A completes after requested B -> published metadata matches A and next accepted B replaces it; rapid frame/display/settings edits retain the previous successful preview without labelling it current.
- Ordered fix 5: add small deterministic scheduler transition checks for held pointer with live on/off, urgent edit while busy, timeline changes, release, focus loss, and framing supersession. Use barriers/explicit completion handles for the worker rather than timing-only sleep tests where possible. No new testing framework is needed.
