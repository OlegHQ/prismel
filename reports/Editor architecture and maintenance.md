# Make Prismel editor boundaries earn trust

Prismel has a sound editor foundation, but **it is not yet justified to call the editor rock solid**. The urgent work is to make save/load preserve every editable state, reject malformed documents before installation, and give UI and viewport input a single owner. The audit reproduced an accepted preset crashing Editor2, an empty saved scene that its own loader rejects, and command-palette scrolling changing both 2D and 3D cameras behind the popup. It also found a source-proven cook-reuse defect, a violated UI construction boundary, and a native framebuffer assertion whose cause remains unresolved. The existing library direction, immutable document, bounded snapshot history, and latest-request cook worker are worth preserving. Apply Ponytail: repair these shared boundaries, reuse the existing intent and history machinery, and extract internal modules before considering one private document library. A broad rewrite, another UI engine, or a generic editor framework would add work without addressing the evidence.

Audit date: 2026-09-27. Baseline: `48c81daa525c91421eb0fd6854332364739ae7fd`. This is an analysis and implementation plan; no production implementation changes were made.

## The current layering is useful; the document seam leaks

The intended dependency direction separates generic state and routing in `editor_core`, widgets/input/painting in `pxui`, generic chrome in `pxui_shell`, SOP presentation in `pxui_graph`, and final composition in `prismel_editor`. Procedural graph authority remains in `Procedural.Edit_graph`; catalog definitions and geometry-to-scene glue have their own libraries. The transitive dependency gate passed **44 libraries, 41 rules, zero listed exceptions**. Shell dependencies contain only Prismel, editor_core, and PXUI, while graph presentation does not import the editor host. These are useful boundaries, not architectural violations. ([Shell dependencies](/Users/snowbear/WORK/GIT/prismel/lib/pxui_shell/dune:1), [graph dependencies](/Users/snowbear/WORK/GIT/prismel/lib/pxui_graph/dune:1), [dependency rules](/Users/snowbear/WORK/GIT/prismel/test/dependency_gate.ml:107))

One immutable `Document.t` owns the scene graph, int-keyed object networks, active camera, and sketch settings. Selection, current navigation level, and cooking sit outside the saved document. History already supports labelled Step/Gesture/Burst/Repair policies, capacity limits, sealing, undo, and redo. Editor2 and Editor3 share `Environment.Make`, so fixes can cover both hosts through one flow. Preserve these choices; there is no evidence requiring command-object history, another graph model, or separate dimensional implementations. ([Document](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/document.ml:14), [history tests](/Users/snowbear/WORK/GIT/prismel/lib/editor_core/test_history.ml:1), [shared environment](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/environment.ml:11))

The important leak is that Document reads and reconstructs `Pxui_graph` presentation state. `Doc.apply` also combines graph edits with view updates. The 1,251-line Core holds document/history, layout/tree/UI, cooking/timeline, persistence, command routing, and caches. Size alone is not a defect; these different reasons to change make the document/view adapter and edit commit policy the appropriate extraction targets. ([View coupling](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/document.ml:35), [combined adapter](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/doc.ml:38), [Core state](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:46))

**The editor violates its stated construction phase rule.** Its rules require panes to return intents and prohibit model/ref mutation inside `Ui.frame`. The pane builder applies graph, tree, parameter, settings, and handle edits while constructing UI, and mutates a local `live` ref. The document values remain immutable: this is a source-proven phase-boundary violation, not demonstrated document corruption. Commit policy has several entry points (`Core.update`, `scene_edit`, `set_settings`, `edit_node`), while viewport edits run afterward. Left-button edits share `Gesture 0`, so unrelated changes can coalesce because a mouse button is held; that consequence is a maintainability/correctness risk, not a reproduced mixed-command failure. ([Rule](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/AGENTS.md:12), [builder edits](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:799), [local mutation](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:829), [history policy](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:1055), [viewport edits](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:1240))

Several apparent problems do not warrant a split. `editor_core` includes file storage and camera serialization, so describing the whole library as pure is inaccurate, but these dependencies are documented. The small Timeline module is an awkward placement, not a reason for a playback library. Host interpretation of operation names is legitimate domain dispatch; the ban applies to graph presentation. No unused-export deletion list was proved. Delete only after compiler-driven dead-code analysis and supported-caller migration. ([Store](/Users/snowbear/WORK/GIT/prismel/lib/editor_core/store.ml:11), [documented layering](/Users/snowbear/WORK/GIT/prismel/specification/backend.md:101), [Timeline](/Users/snowbear/WORK/GIT/prismel/lib/sketch_support/timeline.ml:1), [host rule](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/AGENTS.md:17))

## Reproduced failures outrank speculative restructuring

**Persistence correctness is the top priority.** The real serializer accepted an empty scene, returned success, and wrote a preset that the real loader rejected as `preset references missing node #6`. Empty editable SOP networks have the same representation mismatch: an integer displayed-node reference survives after the nodes disappear. This is a runtime-reproduced save/load contract failure; the reproduction constructs the internal empty graph rather than simulating mouse deletion. It proves an unrestorable self-generated save, not a torn write or measured loss of an older file. Crash-dump presets use the same serializer. ([Reproduction](</Users/snowbear/WORK/GIT/prismel/research_notes/Editor architecture and maintenance/document-repro.ml:1>), [empty display representation](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/document.ml:34), [display reconstruction](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/preset.ml:257), [crash save](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/environment.ml:480))

A second runtime reproduction loaded a v2 geometry object without its network. The loader accepted it, then public Editor2 browser loading raised `Invalid_argument("option is None")`. Missing networks decode as an empty list; unknown network owners are skipped; the 2D host selects geometry without verifying a network and calls an unchecked lookup. This is malformed-input acceptance followed by a host crash, distinct from the valid empty-document contract above. Duplicate saved IDs, duplicate owners, wrong owner kinds, dangling display/camera references, and nonfinite coordinates also need validation; downstream failures for those cases were not reproduced. ([Recorded output](</Users/snowbear/WORK/GIT/prismel/research_notes/Editor architecture and maintenance/document.md:1>), [optional networks](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/preset.ml:177), [owner handling](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/preset.ml:303), [unchecked level](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:141), [post-load choice](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:1080))

**Modal input leaks into viewport navigation.** Opening the command palette and wheeling at `(330,300)` in a 900×640 editor changed 3D camera distance from `7` to `6.20844306` and 2D zoom from `1` to `1.12749685`. Core masks pointer input only for viewport-handle grabs; popup ownership does not suppress the separate camera event fold. PXUI itself already owns capture, focus, ordered events, and blocking roots. The repair belongs at the UI-to-viewport adapter, using that ownership rather than another hit test. Right/middle drag and world-edit leakage follow the same source path but were not separately reproduced. ([UI reproduction](</Users/snowbear/WORK/GIT/prismel/research_notes/Editor architecture and maintenance/ui-repro.ml:1>), [input masking](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/core.ml:1178), [navigation](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/environment.ml:423), [PXUI router](/Users/snowbear/WORK/GIT/prismel/lib/pxui/ui.ml:607))

The same reproduction showed focused text remaining focused after `Shell.frame ~visible:false ~overlay:None` received `WindowFocusLost`. That branch skips `Ui.frame`, so cancellation and pruning never run. This is a generic shell API failure; ordinary editor leader shortcuts generally cannot hide UI while text owns keys. Nontext controls also lack keyboard focus traversal/activation in the inspected toolkit paths. No VoiceOver or Accessibility Inspector session was performed, so this establishes a keyboard-accessibility gap rather than proving the complete native accessibility tree is absent. ([Hidden branch](/Users/snowbear/WORK/GIT/prismel/lib/pxui_shell/pxui_shell.ml:797), [cancellation](/Users/snowbear/WORK/GIT/prismel/lib/pxui/ui.ml:686), [button/toggle activation](/Users/snowbear/WORK/GIT/prismel/lib/pxui/ui.ml:1494))

Cooking has a **source-proven reuse defect**: `previous_settings != Some settings` compares option-wrapper identity against a fresh wrapper, rejecting reuse even when the settings payload is the same. A small OCaml probe confirms that expression. Actual latency and allocation impact were not benchmarked. Fixing the comparison alone is unsafe: reuse also checks graph identity without the timeline/output context, so enabling it can retain stale Time/Frame-dependent geometry. Completed values are additionally stamped with current settings rather than the submission settings. Preserve Async_cook's bounded active/pending requests, supersession cancellation, latest-ID publication, and joined shutdown; add correct result provenance in the host. ([Reuse and stamp](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/cook.ml:140), [dynamic scheduling](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/schedule.ml:25), [worker publication](/Users/snowbear/WORK/GIT/prismel/lib/procedural/async_cook.ml:94))

Command extensions have another deterministic source issue: two supplied entries with the same ID but different closures dispatch the first action even when the second trigger is chosen. Built-in trigger collisions can also leave palette and keyboard behavior inconsistent. Repeated IDs intentionally support aliases, so blanket rejection would break a valid contract. Define canonical identity and conflict policy at construction, preserving aliases and scoped bindings. This was traced, not executed as a command-collision reproduction. ([Construction/dispatch](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/environment.ml:236), [first action lookup](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/environment.ml:452), [alias contract](/Users/snowbear/WORK/GIT/prismel/lib/editor_core/editor_core.mli:44))

## Mature patterns reinforce the existing design

Dear ImGui describes immediate mode as an API relationship that leaves application data with the application; internal retained interaction state is compatible with it. Its integration guidance requires always forwarding input to UI and using UI ownership to decide what reaches the application, including popup and drag cases. Qt Graphics View similarly retains the accepting item's mouse grab until release. The transferable rule is **one owner for an entire gesture**, including cancellation and key-up, rather than hover rectangles or a global boolean. A viewport root is itself clickable, so indiscriminately suppressing input whenever PXUI wants the pointer would suppress legitimate navigation. ([Dear ImGui paradigm](https://github.com/ocornut/imgui/wiki/About-the-IMGUI-paradigm), [integration guidance](https://github.com/ocornut/imgui/blob/master/docs/FAQ.md#q-how-can-i-tell-whether-to-dispatch-mousekeyboard-to-dear-imgui-or-my-application), [Qt scene events](https://doc.qt.io/qt-6/qgraphicsscene.html))

Qt's model/view guidance separates stored data from presentations. ProseMirror's state guidance uses a controlled update point and transactions producing a new immutable state; Qt undo distinguishes compression from explicitly grouped macros. Apply these principles through one small, concrete editor reducer and commit helper. Existing pane intents should carry stable IDs and edits; an explicit label/merge policy should determine history. Document conversion belongs in a view adapter. These sources support separation and transaction semantics, not importing their frameworks or creating a generic bus/plugin/transaction subsystem. ([Qt model/view](https://doc.qt.io/qt-6/model-view-programming.html), [ProseMirror state](https://raw.githubusercontent.com/ProseMirror/website/master/markdown/guide/state.md), [Qt undo stack](https://doc.qt.io/qt-6/qundostack.html))

VS Code reuses command identifiers across keys, buttons, and programmatic invocation. Qt's safe-save interface writes a temporary file and replaces the destination only on success, matching Prismel's existing Store pattern. Retain these existing mechanisms and strengthen identity/validation around them. Temp-file rename proves useful ordinary failure protection; it does not establish power-loss durability without a durability contract. Apple's custom-control guidance supports exposing roles, values, and actions for drawn elements: derive semantics from PXUI boxes and send actions through existing intents. The Apple guide is archived; verify current APIs during implementation. ([VS Code commands](https://code.visualstudio.com/api/extension-guides/command), [Qt safe save](https://doc.qt.io/qt-6/qsavefile.html), [Apple custom controls](https://developer.apple.com/library/archive/documentation/Accessibility/Conceptual/AccessibilityMacOSX/ImplementingAccessibilityforCustomControls.html))

The recommended boundary is modest: host composes and performs effects; document holds validated scene/network/settings data; a reducer applies edits and commits history; a view adapter converts document state to PXUI presentation; cooking publishes a result with its originating snapshot; PXUI remains the sole interaction and painting engine. This is an interpretation of the research applied to the inspected code, not a claim that a particular external framework proves Prismel correct.

## Order repairs by user impact and enforceable guarantees

### P0: establish save/load safety and explain the native red check

First make empty scene/network states explicit and round-trippable. Add one shared document validation boundary before installing loaded state, plus a validated current-level resolver after load, undo, and removal. Reject ambiguous IDs/owners, invalid references, nonfinite values, and host-incompatible content with useful errors. Acceptance means delete-all/save/reload, load undo/redo, and crash-preset reload preserve intentional emptiness in both hosts; rejected loads leave document, history, viewport, and last successful preview unchanged. Decide explicitly whether Editor2 supports an empty scene or rejects it safely, and whether an empty SOP clears its preview. The existing cook fallback retains the previous output, so empty state must not silently impersonate current geometry. ([Fallback](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/cook.ml:124))

In parallel with those repairs, diagnose the native look-through assertion. It fails serially and from the raw executable, and saved pixels differ. However, the editor composes object placement and lights while the reference draws a prepared mesh directly. **This is a reproduced test failure with unresolved cause, not a confirmed production camera/render bug.** Compare equivalent transforms, lighting, viewport, and lens before changing either behavior or the oracle. Acceptance is an explained result and a meaningful passing assertion; bulk fixture promotion or weakened comparisons do not qualify. ([Comparator](/Users/snowbear/WORK/GIT/prismel/test/test_prismel_editor.ml:866), [composition](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/environment.ml:315), [placed nodes/lights](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/viewport3.ml:241))

### P1: repair ownership, transactions, cook provenance, and extension identity

Route viewport input through the existing PXUI owner's unconsumed ordered events, allowing the view root to own navigation. Always advance `Ui.frame` when shell contents disappear, building no boxes except any overlay. Parameterize regression checks over Editor2/3: modal wheel and pointer gestures leave underlying camera/document unchanged; a viewport drag survives crossing panes and ends on release/focus loss; graph-owned gestures never begin navigation; hidden focused/captured controls relinquish ownership. Include same-frame open/close and press/release transitions.

Then move view conversions out of Document and document application after UI construction. Return the `live` value instead of mutating a ref, reuse existing graph/tree/parameter intents, and route UI plus environment edit paths through one history commit helper. Scope gesture grouping by operation/target instead of button state alone. Acceptance checks cover document/history-present agreement across public edits, undo/redo, settings, load, camera following, and gestures; same-frame selection plus inspector edit targets the intended stable node; unrelated commands do not merge during a drag; invalid/cancelled edits change neither history nor document; object transforms still avoid SOP recook.

Repair Cook as one change: carry submission settings and sufficient output/context identity with completed values, then enable reuse. Count prepares for two static objects when only one changes; changing settings prepares both; Time/Frame graphs produce fresh geometry despite unchanged graph identity; delayed results retain their real provenance and are replaced by newer accepted work. Exercise scheduler transitions and shutdown using explicit completion/barrier controls where possible. Record elapsed time, allocations, object sizes, domain count, and machine before/after this hot-path change. Finally, validate supplied command identity/trigger conflicts at the existing result-returning create boundary, checking valid aliases, scoped bindings, and keyboard/palette action equivalence. No new worker or command registry is needed.

### P2: add a private document library only when it buys enforcement

After internal extraction, consider **one private `editor_document` library** containing UI-free Document, Settings, Objects, Layers, Preset, and transitions. The gate is concrete: either a real second consumer needs the model independently, or the compiler-enforced presentation ban is worth maintaining. The library must not reach PXUI, shell, graph presentation, sketch_support, or prismel_editor; add a transitive dependency rule and injected bad-edge check. If extracted code still needs UI, the split is premature. Keep public Editor2/3 APIs stable unless a deliberate change is reviewed. Internal module separation alone improves review but cannot enforce this import ban because library modules share dependencies.

Remove proven cruft afterward: migrate Workspace tests to public Shell Layout/Chrome, then remove the three-line compatibility facade if supported callers are gone; decide the stability contract of publicly exposed `Private` hooks; correct stale layout shortcut comments; document prepare callbacks' worker-domain restriction at Editor2/3. Add keyboard traversal/activation using PXUI's existing boxes, then native semantics through the same intents. Bound or prune the persistent modal-height cache if dynamic keys are supported. Avoid a docking/plugin framework, new reactive layer, new persistence system, or a broad widget-engine split without a demonstrated requirement. ([Workspace facade](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/workspace.ml:1), [public hooks](/Users/snowbear/WORK/GIT/prismel/lib/prismel_editor/prismel_editor.mli:40), [stale comment](/Users/snowbear/WORK/GIT/prismel/lib/pxui_graph/pxui_graph.mli:166), [worker contract](/Users/snowbear/WORK/GIT/prismel/lib/procedural/async_cook.mli:1), [modal cache](/Users/snowbear/WORK/GIT/prismel/lib/pxui/ui.ml:464))

## Passing gates must cover the repaired contracts

The baseline passed `@check`, editor_core/PXUI/shell logic, graph/editor logic, scene-tree, dependency, catalog, SOP UI, sketch-support, and API-manifest checks. Existing catalog tests already instantiate factories and perturb cook-impact fields; reuse them. The dependency parser ignores nested library expressions and unknown names, although current editor stanzas fit it. Treat this as prospective coverage debt, not evidence of a current bypass. Guard changed boundaries with small behavioral checks and explicit gate fixtures rather than a new architecture analyzer. ([Catalog checks](/Users/snowbear/WORK/GIT/prismel/test/test_sop_catalog.ml:292), [gate parser](/Users/snowbear/WORK/GIT/prismel/test/dependency_gate.ml:39))

An initial simultaneous native invocation failed both suites. Isolated serial PXUI parity subsequently passed (`overlay parity: exact`; 640×600 at 2× with 272 permitted changes). The editor look-through test still failed at line 883 serially and as a raw executable. Concurrency contamination is a possibility, not measured causality. Native suites should be deliberately sequenced, and the passing logic aliases cannot substitute for them. ([Parity comparator](/Users/snowbear/WORK/GIT/prismel/lib/pxui/test_ui_parity.ml:88), [native assertion](/Users/snowbear/WORK/GIT/prismel/test/test_prismel_editor.ml:883), [validation notes](</Users/snowbear/WORK/GIT/prismel/research_notes/Editor architecture and maintenance/ui.md:1>))

Use the existing focused checks while implementing:

```sh
dune build @check @lib/editor_core/runtest @lib/pxui/runtest @lib/pxui_shell/runtest @test/test_pxui_graph @test/test_prismel_editor_logic @test/test_scene_tree @test/test_sop_catalog @test/test_sop_ui @test/test_sketch_support @test/dependency_gate @tools/api_manifest/runtest
```

Run native complements sequentially on the real display/Metal:

```sh
dune build @lib/pxui/test_ui_parity && dune build @test/test_prismel_editor && dune build @smoke
```

Future implementation completion requires the acceptance checks above, reviewed intended API-manifest changes, updated architecture/API notes and examples where behavior changes, `@doc`, and the repository gate:

```sh
dune build @all && dune runtest && dune build @smoke && git diff --check
```

The audit did not benchmark performance/history memory, run native accessibility tooling, prove every command conflict or mixed-gesture failure, or investigate disk-full/power-loss durability. Reproduction sources and detailed qualifications are preserved in the [research notes](</Users/snowbear/WORK/GIT/prismel/research_notes/Editor architecture and maintenance/document.md:1>). These limitations constrain claims of readiness; they do not weaken the demonstrated persistence and ownership defects.

The maintainability test is whether each document edit, input gesture, loaded state, and cook result has one obvious validation/ownership path and one small check that fails when it breaks. Library count and file length cannot establish that. Once these contracts hold, the optional document split becomes a decision about enforcing an already-clear boundary, rather than an attempted cure for behavior that still crosses it.
