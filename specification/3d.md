# 3D rendering

Status: foundational software renderer implemented; openFrameworks parity is
tracked in [`3d-parity.md`](./3d-parity.md).

## Design

Prismel keeps 3D scene construction pure and rasterization at the same effect
boundary as 2D rendering:

```text
Mesh / Material / Light / Camera / Shader3
                │ immutable values
                v
             Scene3.t
                │ Scene.view3d
                v
          Scene.render (effect)
                │
          ┌─────┴──────────────┐
          v                    v
 native OpenGL GPU       headless/web CPU
 depth + raster          color/depth raster
          │                    │
          └──────> active SDL renderer/presenter
```

The CPU framebuffer is deliberate for headless/web reference execution:
`HEADLESS=1` exercises real perspective projection, lighting, culling, and
per-pixel depth without a display, GPU, or OpenGL context. Native untextured
fixed-pipeline scenes instead use OpenGL hardware transforms, depth/stencil,
lighting, culling, blending, rasterization, and window MSAA. The immutable
public scene remains shared. Textures, typed shaders, shadows, fog, and
separate-specular rendering are the remaining native GPU parity tranche and
currently take an explicit software fallback rather than silently changing
their semantics.

All 3D coordinates are floats. Angles remain radians, matching the rest of
Prismel. `Scene.view3d` viewports are logical points. The software path lets SDL
map the final texture to native backing pixels; the native GPU path converts
both logical viewport edges to physical drawable coordinates before setting
OpenGL viewport/scissor state. This edge conversion preserves exact adjoining
pane boundaries and prevents half-sized/clipped Retina sub-viewports.

## Public values

- `Mat4` supplies affine/projective composition, inversion, perspective,
  orthographic, and look-at matrices.
- `Camera` supplies immutable perspective, orthographic, explicit frustum, and
  off-axis portal cameras; local motion/orbit; optional vertical projection
  flipping and forced aspect ratio; world/screen/camera conversion; picking
  rays; image-plane distance; and a frustum diagnostic mesh.
- `Easy_camera` supplies a functional pointer-driven orbit/pan/dolly model
  with remappable button/key interactions, bounded control areas, inertia,
  sensitivities, configurable FOV and clipping, configurable up behavior,
  auto-distance, and double-click reset. `Pxui.Camera_control` supplies the
  reusable resize-aware UI and keyboard policy around it.
- `Easy_camera2` is the corresponding non-perspective world-view camera for
  2D sketches. It supplies center/zoom/rotation, world/screen conversion,
  pointer-anchored trackpad zoom, captured middle/right/Space pan, and pure
  clipped `Scene` composition. `Pxui.Camera2_control` supplies matching C/H,
  reset, and render controls without importing SOP machinery.
- `Quat` and `Node3` supply reusable orientations, persistent parenting,
  maintain-global reparenting, global/local transforms and coordinate
  conversion, Euler queries, global orientation updates, rotate-around,
  look-at, orbit, and local-axis motion.
- `Mesh` stores vertices, indices, normals, colors, and normalized texture
  coordinates. It supports points, lines, line strips/loops, triangles,
  triangle strips, and triangle fans. Safe optional getters, immutable
  per-element/full-attribute replacement, safe removal, range coloring,
  duplicate merging, centroid and compact submesh queries, angle-aware smooth
  normals, and attributed triangle-face records cover mesh editing and
  inspection.
- `Mesh.plane`, `box`, `sphere`, `icosphere`, `cylinder`, and `cone` generate
  indexed geometry with normals and texture coordinates. Box sides are
  individually addressable and radial cap resolution is configurable.
  Icospheres share midpoint vertices, yielding `10 * 4^n + 2` vertices and
  `20 * 4^n` faces at subdivision level `n` rather than triangle-local copies.
- `Mesh.axis`, oriented `grid_plane`, `rotation_axes`, `arrow`, and
  `normal_lines` provide OF-style spatial diagnostics.
- `Mesh.load_ply` reads the ASCII PLY format used by `ofMesh`; `save_ply`
  writes ASCII plus little- and big-endian binary PLY. OBJ loading/saving
  additionally preserves independent position/normal/UV indices through
  deterministic vertex expansion.
- `Texture` supplies immutable CPU pixels with nearest/bilinear/trilinear
  sampling, deterministic mip-chain generation, automatic triangle LOD,
  clamp/repeat/mirror wrapping, and pixel-accurate subsection copies. Mesh UVs
  interpolate perspective-correctly and can be remapped to a subsection.
- `Shader3` supplies programmable CPU vertex, geometry, and fragment stages,
  immutable typed uniforms (including textures and matrices),
  perspective-correct custom varyings, fragment discard, and optional
  fragment-depth output. `Transform_feedback3` captures vertex/geometry output
  and `Compute3` provides deterministic functional 3D workgroup dispatch.
- `Fog3` supplies validated linear, exponential, and exponential-squared
  distance fog evaluated from interpolated world position per fragment.
- `Shadow3` binds a captured normalized depth map to one light and supplies
  hard, 3×3 PCF, or 5×5 PCF sampling with constant and normal-angle bias.
- `Material` supplies diffuse, ambient, specular, emissive, and shininess
  properties.
- `Light` supplies ambient, directional, point, spot, and area lights.
- `Scene3` supplies hierarchical translation, axis-angle rotation, scaling,
  filled faces, wireframes, vertices, smooth/flat shading, and
  front/back/disabled culling. Scoped raster state controls logical line width,
  point size, and replace/alpha/add/multiply/screen/subtract blending.
- `Framebuffer3` runs the shared raster core offscreen and retains immutable
  color, normalized-depth, and 8-bit stencil attachments. Its color attachment
  is directly reusable as a `Texture.t`.
- `Render3.save_png` renders an explicit still-image size. Supported native
  scenes use an isolated OpenGL framebuffer; headless and unsupported native
  scenes use the deterministic software implementation.
- `Render2.save_png` renders a logical 2D camera viewport at an integer factor
  through the deterministic software canvas. Native interactive 2D remains
  accelerated, while this still-export boundary is intentionally portable and
  does not claim the native 3D GPU path.
- `Scene.view3d` embeds a complete 3D scene in an ordinary `Scene.t`.

Meshes and scene nodes are immutable. Reusable geometry is built once and
shared between frames. `Mesh.transformed`, `Mesh.recalculate_normals`, and
`Mesh.append` return new values.

The renderer borrows the mesh's persistent immutable arrays directly. Weak
identity-keyed caches retain prepared normals, flat-shaded expansion, and
primitive topology for repeated frames and `Scene3.instances`; cache entries
cannot keep otherwise unreachable meshes alive. This is the software-backend
equivalent of persistent VBO geometry, without introducing an OpenGL
requirement into the public API.

`Scene3.instances_array` copies one packed transform array at construction and
shares the prototype mesh. Rendering visits one batch descriptor per scene
node and streams its transforms; it does not first expand instances into a
retained drawing list. `Procedural.Bridge.cook_to_scene3` is the
allocation-preferred typed SOP boundary for this path; the lower-level
`cook_to_instances` returns an owned array for custom assembly. Packed
instances are terminal render data—materialize real PDK topology before
operations that need to edit individual copies.

## Camera and depth conventions

The camera is right-handed, looks toward local negative Z, and uses positive Y
as its up direction. Perspective FOV is vertical. Projection maps depth into
the normalized `[0, 1]` interval, where smaller values are nearer.

`Camera.off_axis_portal` derives an asymmetric projection from an eye position
and three portal corners. It is suitable for projection mapping and
multi-display installations where the eye is not centered on the display
plane. `Camera.with_v_flip` mirrors the projection vertically without changing
world transforms. `Camera.frustum_mesh` returns the twelve near/far-plane and
connecting edges as an ordinary line mesh that can be rendered through
`Scene3`.

The 3D renderer creates one depth buffer for each `Scene.view3d` node. All mesh
nodes in that `Scene3.t` compete in the same depth buffer regardless of
declaration order. A later 2D scene node intentionally draws over the completed
3D viewport.

Opaque fragments update the depth buffer immediately. Translucent fragments in
front of the nearest opaque surface are retained per pixel, sorted
back-to-front, and source-over composited before the 3D texture is uploaded.
Transparent output then composes correctly over earlier 2D scene nodes.
`Scene3.with_blend` can instead select replace, additive, multiply, screen, or
subtract composition for a scoped subtree.

`Scene3.create ~samples` selects deterministic 1, 4, 9, or 16-sample coverage.
The renderer rasterizes at the corresponding square sample grid and resolves
premultiplied color and alpha into the logical-point viewport.

Back-face culling is enabled by default. Counter-clockwise world-space faces
are front-facing before the screen-space Y flip. `Cull_none` is useful for
open surfaces such as a floor viewed from both sides.

## Depth, stencil, and offscreen targets

Depth defaults to `Less` comparison with writes enabled and a normalized clear
value of `1`. `Scene3.with_depth` scopes any comparison mode and independently
controls writes. `Scene3.create ~depth_clear` supports reversed/custom depth
passes.

Stencil is an 8-bit attachment cleared to zero by default.
`Scene3.with_stencil` scopes reference/read/write masks, all standard
comparisons, and keep/zero/replace/increment/decrement/wrap/invert operations
for stencil-fail, depth-fail, and pass outcomes. Stencil comparison happens
before depth comparison, matching the conventional graphics pipeline.
`Scene3.with_raster` independently scopes logical line width and point size.
Those sizes remain logical under multisampling; the supersampled raster scales
them before coverage resolve.

`Framebuffer3.render ~width ~height ~camera scene` uses the same clipping,
shading, depth, stencil, transparency, and multisample code as
`Scene.view3d`. It exposes copied depth/stencil arrays and pixel access, while
the immutable color attachment is borrowed as a `Texture.t`. A second
Framebuffer3 pass can therefore perform deterministic post-processing with
`Shader3`; `to_canvas` and owned `to_image` snapshots bridge back to 2D scenes.
When multisampling, color resolves by premultiplied averaging, depth resolves
to the nearest sample, and stencil resolves by bitwise union.

## Shadows

Shadow maps use the ordinary offscreen path:

1. render caster/receiver depth with `Framebuffer3.render` from a light camera;
2. create a light-bound map with `Framebuffer3.shadow`;
3. pass it through `Scene3.create ~shadows` with the same immutable `Light.t`.

The renderer projects interpolated world positions into each matching light
map per fragment. Only that light's diffuse and specular contribution is
attenuated; ambient and emissive material energy remain visible. `Shadow3.Hard`,
`Pcf_3x3`, and `Pcf_5x5` trade sharpness for deterministic filtering.
Constant bias and normal-angle bias address self-shadowing, while `strength`
allows partially transmissive artistic shadows. Points outside a shadow
camera's clip volume remain lit.

## Lighting

Lighting uses normalized mesh normals and a Blinn-Phong material model:

- global and per-light ambient response;
- Lambert diffuse response;
- specular response controlled by material shininess;
- constant, linear, and quadratic attenuation for local lights;
- cutoff and concentration for spotlights.

Rectangular area lights average deterministic 1, 4, 9, or 16-point surface
grids. The default is nine samples. This preserves repeatability while allowing
the caller to trade render cost for smoother spatial response.

`Scene3.create ~separate_specular:true` applies specular energy after mesh
texture modulation, equivalent to openFrameworks' separate-specular lighting
control. Its default is false, so diffuse and specular light are combined
before texture sampling.

`Scene3.create ~fog` applies standard distance fog after fixed
lighting/texturing and before an optional custom fragment stage. Fog preserves
surface alpha while blending RGB toward its configured color.

`Material.unlit color` places the color in the emissive channel. It is useful
for diagnostics, UI-like 3D elements, and deterministic depth tests.

When fixed lighting can be collapsed at vertex processing time, points, lines,
and triangles all consume the collapsed color directly. Lit line and point
rasterization must not index the intentionally empty per-light arrays; rendered
procedural curve regressions exercise this path.

## Programmable stages

Pass `~shader` to any `Scene3.mesh`, primitive, or `instances` node. The vertex
stage receives the mesh attributes, vertex index, model/view/projection and
normal matrices, and immutable uniforms. It returns clip-space position,
world-space position and normal, color, texture coordinate, and a declared
number of scalar varyings. Varyings, world values, colors, and texture
coordinates survive homogeneous clipping and interpolate perspective-correctly.

An optional geometry stage receives each transformed point, line, or triangle
and may emit any number and mixture of those primitive kinds. Emitted geometry
passes through the same six-plane homogeneous clipping, culling, depth,
stencil, lighting, and fragment path.

The fragment stage runs for covered triangle, line, and point samples. It
receives logical sample position, depth, facing, interpolated values, the
fixed-pipeline lit/textured color, and the same uniforms. It may return a color,
override normalized depth, or discard the fragment without touching color or
depth. Use `Material.unlit Color.white` when a shader should replace fixed
lighting rather than post-process it.

`Transform_feedback3.capture` runs the vertex and optional geometry stages
without rasterization and returns primitive, vertex, varying, and attributed
mesh views. `Compute3.dispatch` invokes a pure function over deterministic
global/local/workgroup IDs, preserves row-major result order, and uses the
reusable `Parallel` pool for coarse workloads.

`Shader3` deliberately expresses stages as typed OCaml functions. This makes
the programmable path deterministic and available without OpenGL or a GPU.
Runtime GLSL string/file syntax is an intentional API difference, not a
missing rendering stage: OCaml modules provide ordinary source-file
composition and compile-time typing while executing on the software reference
backend.

## Resource and domain behavior

Scene3 values own no SDL resources. Headless/web and unsupported native scenes
upload the completed CPU framebuffer through a reusable RGBA streaming texture.
Supported native scenes borrow bounded packed mesh views through OpenGL client
arrays and execute the 3D pipeline on the GPU; the cache retains at most the
current and previous procedural mesh per shading mode. All SDL/OpenGL calls
remain on the initial domain. Raw Scene3 passes preserve SDL's compatibility
state and explicitly clear inherited shader, VBO, element-buffer, and 2D texture
bindings on every frame before using fixed-pipeline client arrays. Mesh
generation, matrix operations, and other pure CPU work may run through
`Parallel`.

The renderer rejects invalid camera frusta, non-positive viewport dimensions,
out-of-range mesh indices, mismatched vertex attributes, invalid light
directions, invalid primitive resolutions, and shader outputs whose varying
count differs from the shader declaration at their public boundaries.

## Parity boundary

The parity matrix is authoritative. Prismel targets equivalent visible
rendering behavior, not mutable C++ names, OpenGL object identifiers, or
runtime GLSL syntax. GPU-only storage/layout details are deliberately absent
from the public API; typed stages, immutable resources, and functional compute
results cover their rendering roles on both visible and headless backends.
